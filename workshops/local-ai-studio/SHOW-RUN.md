# Presenter talk track: make the room investigate

Use the visual guide's **Present one lab** control. Start the timer yourself.
Previous/Next, sidebar links and Left/Right on the page move between labs;
focused buttons/links retain their normal keyboard behavior. **Full guide** restores
the scrollable document. No timer or discussion control invokes a provider.

Prepare the real model and optional own-project Langfuse before the room arrives.
Use the existing detailed runbook for all setup/commands. This talk track adds
pacing and questions; it does not replace the technical gates.

## First 60 seconds

“The alert is simple: payments is slow. In the next hour, we will build an agent
that can investigate it. Before we start: would you let it restart payments?”

Take two answers. “Keep your prediction. We'll test an explicit change request
later. First we need an investigator that collects evidence instead of guessing.”

Show the synthetic brief. Do not open with a product catalogue, architecture tour
or a claim that the model knows the cause. The audience needs a job to solve.

## Eight beats

| Minute | Visible action | Ask the room | Show the answer through evidence |
|---|---|---|---|
|00–05|Scaffold an empty learner; expected RED|What can a role prompt authorize?|The task contract and absent runtime capabilities|
|05–14|Codex creates the core; review and run contracts|Which lines make this an agent?|The native loop, registry, validation and stop conditions|
|14–23|Run that exact file in the chat|How do we know a tool actually ran?|Actual call, observation and matching event, not prose|
|23–32|Add release_diff with strict arguments|Recent release: cause or clue?|Synthetic timeout change; causality remains unconfirmed|
|32–42|Follow one turn through metadata|Does flush mean verified?|Local record, exporter result, independent exact readback|
|42–50|Retrieve a forged instruction; request a change|Can the document add a capability?|Unchanged registry and pre-model policy stop|
|50–56|Fail the training source; compare models|Can a fluent answer erase a failed tool?|The retained error, reported usage and actual outcomes|
|56–60|A participant narrates one turn|What would you need to reproduce this?|Reviewed source, commands, actual receipts and missing gates|

## Three moments worth pausing for

**Before the release observation:** ask for a show of hands on rollback. After
reading the result, ask what independent measurement could distinguish a timeout
configuration issue from downstream saturation. Do not manufacture evidence for
an answer; the fixture is intentionally insufficient for a causal conclusion.

**Before opening the forged runbook:** ask whether a retrieved document can grant
a permission. Run the real case once, keep what happened and inspect the boundary.
A denied tool call can be more instructive than a perfectly phrased refusal.

**Before readback:** write the session and trace roles on screen, then query the
exact trace. If it is absent, diagnose delivery without spending another model
turn. Successful export still is not the same receipt as backend acceptance.

## Keep the hour moving

Let each prediction take 20–30 seconds; avoid a general debate. Show one relevant
function at a time. Keep the four diagrams available for a question; do not narrate
every box before the app exists. Use the architecture view after a real turn so
people can map a visible result to each component.

If coding takes too long, keep the transcript and explicitly switch to the
instructor lane. If the model fails, explain the actual failure and continue
local contract/policy work. If telemetry is blocked, preserve local evidence and
leave ingestion pending. A prepared reference helps pacing; replaying it as a
fresh successful creation would destroy the lesson.

## Last 60 seconds

Ask someone to finish these sentences: “The model proposes…”, “The harness
permits…”, “The tool returns…”, “The trace proves…”, “What is still unverified…”

End by handing over the repository revision and the repeat commands. Keep
personal configs, keys, transcripts and captures out of the shared material.
