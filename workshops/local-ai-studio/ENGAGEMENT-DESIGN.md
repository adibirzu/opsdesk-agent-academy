# Make the workshop an investigation

Design decision for this local iteration: keep the existing olive/ivory visual
language, but run the hour as one incident with predictions and evidence reveals.
This is an author-selected approach based on the user's request for a more
interesting applied session. It is not audience research or live acceptance.

A lecture-first architecture tour delays the useful app. A timed competition
would reward fast guesses. Use an investigation instead: people predict, build,
observe a real result, and explain the boundary. No simulated model answers,
fabricated activity, success score or automatic provider traffic.

## Story

Payments latency is high in an explicitly synthetic training system. A release
record is temporally close. The agent must distinguish correlation from cause,
use constrained read-only tools, reject a forged runbook instruction, preserve a
failed source, and stop before any change. The audience chooses what evidence is
missing; the harness determines which actions can actually run.

## UI principles

One visible task at a time in presentation mode. Put the question before the
answer. Label synthetic inputs and evidence limitations at the point of use.
Every control works with keyboard and touch. Existing scrollable guide remains
available; presentation mode is an explicit choice, not a new runtime authority.

## Source ownership

this local implementation plan.
