[00:39] The early change stop is one guardrail. Others validate the request shape, the selected service, each tool argument, maximum calls, output size, quota, and error handling. Explain that boundary in the prompt, but enforce what you can in code. A ticket cannot add a shell tool if the registry contains only two read-only fixtures. A model cannot query another service if argument validation rejects the mismatch. A tool exception should end or fail the bounded operation honestly, not cause a silent unrestricted retry. No single test proves universal injection resistance. We demonstrate specific controls and keep their practical limits visible.

[01:25] The ordinary user sees an answer or failure. The operator needs to understand the operation behind it. How many model calls occurred? Which tools ran? Did the policy stop the request before inference? How long did the calls take? Did export fail, and at which safe diagnostic stage? Parent and child relationships help us connect the application request, authorization, generations and tools without pretending that every event is an independent application.
