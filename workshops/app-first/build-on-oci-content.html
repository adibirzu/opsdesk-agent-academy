Build it in six checkpoints

  1. Prepare your scope. Select your compartment, region, project and authentication method. Review model access and retention. Keep the values private; use the current Console and official quick start.
  2. Connect the model on the server. Keep credentials out of browser code. Start with one synthetic response before adding tools. OCI model availability must be checked for your own region and account.
  3. Add the existing tools. Keep service_health and release_diff as synthetic, read-only functions. Limit model calls to three. An explicit restart must return approval_required before inference.
  4. Add knowledge only when needed. Consider File Search and vector stores for authorized runbooks. Conversations and project memory add state: choose retention deliberately. Add MCP only for named, approved tool servers.
  5. Instrument and verify. Export allowlisted execution metadata. Find the exact run separately in every selected destination. Show reported tokens, duration and a dated cost estimate; leave missing values unknown.
  6. Review, deploy, retest. Prepare an image and OCI Container Registry reference. Review application authentication, endpoint exposure, network access, scaling, storage, cost and rollback before creating or activating a deployment. Repeat the original app journey afterwards.
